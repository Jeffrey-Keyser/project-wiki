# Glossary

Shared vocabulary is maintained in `docs/DOMAIN-GLOSSARY.md`. This page summarizes the key terms. For how they fit together, see [Architecture](../architecture/).

## Runs, plans, and roles

- **Run.** One standalone orchestration. Its state lives in `results/<runId>/` ([README.md:L151-L152](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/README.md#L151-L152)).
- **Dispatch event log.** `dispatch-events.jsonl`, the canonical record of run state transitions. Its events wake barriers, and the matching artifacts confirm completion ([CLAUDE.md:L14](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/CLAUDE.md#L14)).
- **Writer of record.** The role or manager writer that owns an artifact body such as `result.json` or `review.json`. Projection never replaces it ([CLAUDE.md:L14](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/CLAUDE.md#L14)).
- **Plan / Slice.**
  - A plan is a multi-slice state-machine aggregate stored in `plans/<planId>/` ([docs/DOMAIN-GLOSSARY.md:L103](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/docs/DOMAIN-GLOSSARY.md#L103)).
  - A slice is one typed plan entry; it is either task-backed or a sub-orchestration ([docs/DOMAIN-GLOSSARY.md:L104](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/docs/DOMAIN-GLOSSARY.md#L104)).
- **Slice acceptance vs task acceptance criteria.** Two distinct contracts. The plan compiler translates slice acceptance into task acceptance criteria ([docs/DOMAIN-GLOSSARY.md:L27-L33](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/docs/DOMAIN-GLOSSARY.md#L27-L33)).
- **plan-managerd.** The sole Go plan-manager runtime, built with `bin/build-plan-managerd.sh` ([CLAUDE.md:L26](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/CLAUDE.md#L26)).
- **Supervise tick.** The `plan.supervise.tick` heartbeat. Its payload carries a `supervise-health/v1` outcome ([systemd/README.md:L142-L145](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/systemd/README.md#L142-L145)).
- **Resume provenance.** The origin (`operator` or `automation`), actor, and cause recorded when a held plan is resumed through `plan-managerd resume`. Public invocations default to operator origin and require an explicit actor and reason. Automation callers such as the self-heal and queue-manager retry recipes pass their own origin context. Automation origin is attribution only and does not certify that no human intervened ([cmd/plan-managerd/slice_lifecycle.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b36a5ddfe9d70380268d99efa8ad591e13bdb9f8/cmd/plan-managerd/slice_lifecycle.go), [cmd/plan-managerd/selfheal.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b36a5ddfe9d70380268d99efa8ad591e13bdb9f8/cmd/plan-managerd/selfheal.go), [cmd/dev-inbox-queued/queue_manager.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b36a5ddfe9d70380268d99efa8ad591e13bdb9f8/cmd/dev-inbox-queued/queue_manager.go)).
- **Task mode.** One of three modes ([CLAUDE.md:L61-L65](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/CLAUDE.md#L61-L65)):
  - `implementation`, the default;
  - `design`, which produces a sourced markdown deliverable;
  - `release`, an explicitly authorized release action.
- **Scout vs prospector.**
  - A scout does per-task, read-only enrichment that is injected into the worker's context.
  - A prospector generates ideas, persisted to `results/prospector-choices.jsonl` ([CLAUDE.md:L78-L79](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/CLAUDE.md#L78-L79)).
- **Observer mode.**
  - `live`, the default, monitors the run as it happens.
  - `terminal` runs once against a deterministic `run-observe brief` ([README.md:L109-L113](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/README.md#L109-L113)).

## Review and verification

- **Slot.** One entry in the filesystem semaphore under `results/.slots/`, which caps concurrent agent CLIs at 12 ([CLAUDE.md:L99](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/CLAUDE.md#L99)).
- **Review tier.** `trivial`, `small`, or `full`. A `trivial` diff skips the LLM and receives a synthetic approve ([CLAUDE.md:L101](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/CLAUDE.md#L101)).
- **Revision loop.** A revision worker that answers `request-changes`, bounded by `maxRevisions` (default 3) ([CLAUDE.md:L102](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/CLAUDE.md#L102)). A revision that leaves the reviewed `reviewedHeadSha` unchanged from the previous attempt's archived review is held as no progress before another revision is spent ([internal/reviewacceptance/stall.go:L81-L96](https://github.com/Jeffrey-Keyser/dev-inbox/blob/78402b9ca152bc8a108473de0c83754a1bb6bc46/internal/reviewacceptance/stall.go#L81-L96)).
- **Scope downgrade.** A pure over-reach `request-changes` is routed as `approve-with-followup`. This happens when every blocking issue cites a declared slice boundary ([CLAUDE.md:L104](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/CLAUDE.md#L104)).
- **Readable verification receipt.** The admission rule for merge-producing review decisions. The `verify.json` bytes must parse as a JSON object. Missing, unreadable, malformed, empty, or non-object JSON (`null`, arrays, scalars) holds with a `verification-evidence` reason. A readable empty object is admitted for readability, but command-evidence sufficiency is judged separately. Command-result qualification adds a further gate: a nonempty `commands` array merges only when every entry records an explicit integer `exitCode`. Absent, null or malformed exits hold with a `command-result` diagnostic and are never read as success. An absent, null or empty `commands` list no longer passes on its own. It holds with an evidence diagnostic unless the executor recorded an explicit skip, meaning `status` is `skipped` with an empty `commands` array, and that skip is bound to a uniquely selected design task in the enclosing canonical run plan. The loader derives the task identity and plan location from the task directory layout and projects the task mode through the shared plancompiler selection. Only an exact `design` mode qualifies. Missing or unreadable plans, absent or duplicate task identities, invalid modes, non-canonical task directories, and any mode other than design hold the skip, and receipt fields, environment values and caller flags grant no authority. Complete nonempty command evidence never triggers this lookup. Non-merge decisions are not changed by these rules. The `accept decide` and `review decide` outputs expose readability as `verify.readable` and `verify.diagnostic`, command-result qualification as `verify.commandsComplete` and `verify.commandResultsDiagnostic`, the evidence state as `verify.evidencePresent`, `verify.explicitSkip` and `verify.evidenceDiagnostic`, and the canonical-design qualification as `verify.canonicalTaskMode`, `verify.canonicalDesignQualified` and `verify.canonicalModeDiagnostic` ([internal/reviewacceptance/accept.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b2a0ab5021e828d7a5cbafd6acdfa6bcc7677e2c/internal/reviewacceptance/accept.go), [internal/plancompiler/canonical_task_mode.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b2a0ab5021e828d7a5cbafd6acdfa6bcc7677e2c/internal/plancompiler/canonical_task_mode.go), [cmd/plan-managerd/accept.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b2a0ab5021e828d7a5cbafd6acdfa6bcc7677e2c/cmd/plan-managerd/accept.go), [docs/manager-verification-execution.md](https://github.com/Jeffrey-Keyser/dev-inbox/blob/274c947e1f82099c5d7df56e221ac1064c15e377/docs/manager-verification-execution.md), [docs/review-acceptance-command-results.md](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b2a0ab5021e828d7a5cbafd6acdfa6bcc7677e2c/docs/review-acceptance-command-results.md)).
- **Submit-check.** A read-only in-loop validator that returns either a normalized draft or a coded correction ([cmd/scout-submit-check/main.go:L3-L8](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/cmd/scout-submit-check/main.go#L3-L8)).
- **Assurance receipt.** Immutable, write-once evidence of one trusted verification pass ([docs/assurance-receipts.md:L3-L8](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/docs/assurance-receipts.md#L3-L8)).
- **Cleanup provenance.** A structured `cleanup_decision` recorded before any worktree or session removal ([docs/cleanup-provenance.md:L3-L8](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/docs/cleanup-provenance.md#L3-L8)).
- **Command result presence.** For directive-reading v8, a consumed verify.json command counts as passing only when its exitCode is present as an explicit integer zero. An absent or null exitCode is incomplete evidence, and a malformed consumed document is disclosed rather than skipped. Legacy lifecycle output still projects absent exitCode as zero ([cmd/orchmeasure/lifecycle_receipt.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b36a5ddfe9d70380268d99efa8ad591e13bdb9f8/cmd/orchmeasure/lifecycle_receipt.go), [internal/measurement/directive_reading_v8.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b36a5ddfe9d70380268d99efa8ad591e13bdb9f8/internal/measurement/directive_reading_v8.go)).

## Work queue

- **Batch → Job → Attempt → Intent.** The queue aggregate chain. A retry adds a new Attempt rather than replacing the Job ([docs/DOMAIN-GLOSSARY.md:L36-L42](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/docs/DOMAIN-GLOSSARY.md#L36-L42)).
- **Operator retry attribution.** `dev-inbox-queued job retry --actor <id> --reason <text>` requires both flags. They are trimmed and validated before the queue is opened. For a failed job, the reason is journaled on the `failed` → `queued` transition, with `retried-by: <actor>` as the first evidence entry. A blocked job also reconciles its recorded process first. Automated recovery keeps the reasonless `Store.Retry` path, whose events still replay ([cmd/dev-inbox-queued/cli_retry.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/dbbec0ef09f905e9164a6d3bdf8c63a485b093bd/cmd/dev-inbox-queued/cli_retry.go), [internal/workqueue/application.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/dbbec0ef09f905e9164a6d3bdf8c63a485b093bd/internal/workqueue/application.go), [docs/work-queue-operations.md](https://github.com/Jeffrey-Keyser/dev-inbox/blob/dbbec0ef09f905e9164a6d3bdf8c63a485b093bd/docs/work-queue-operations.md)).
- **Shadow / released bake / unattended.** The three daemon modes. Shadow is the default ([cmd/dev-inbox-queued/main.go:L155-L174](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/cmd/dev-inbox-queued/main.go#L155-L174)).
- **`DEV_INBOX_QUEUE_MAX_ACTIVE_JOBS`.** The global cap on concurrently active outer jobs. Each repository is still limited to one active job ([cmd/dev-inbox-queued/main.go:L243-L248](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/cmd/dev-inbox-queued/main.go#L243-L248)).

## Measurement

- **Reading.** A read-only, provenance-carrying measurement result produced by `orchmeasure` ([docs/DOMAIN-GLOSSARY.md:L68](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/docs/DOMAIN-GLOSSARY.md#L68), [docs/KEY-PATHS.md:L73](https://github.com/Jeffrey-Keyser/dev-inbox/blob/9a72cd60e5068bd14367dc5f7f9acd50e387b650/docs/KEY-PATHS.md#L73)).
- **Manager invocation accounting.** A `plan.invocation_usage` record for one manager decomposition, initialization, wake, or correction attempt. It carries numeric provider-reported usage when the native stream is valid, and `unavailable` or `partial` otherwise. Accounting is plan-scoped: shared plan usage is not allocated across runs or tasks, and no realized savings or production coverage is claimed ([docs/manager-control-usage-accounting.md](https://github.com/Jeffrey-Keyser/dev-inbox/blob/f1c7fd60982b2c82333aab0e7bc5692b7cfd8697/docs/manager-control-usage-accounting.md)).
- **Directive-reading v8 (explicit verification exit).** An explicitly selected `orchmeasure directive-reading --reading-version v8` definition. It requires both `--queue-journal DIR` and `--plans-dir DIR`, and it composes the v7 aggregate and partitions from qualified run facts. Missing, null or malformed consumed command-result evidence cannot establish passing verification, and exclusions are disclosed with run, task, source path and exact-byte digest. The report keeps its upper-bound and inconclusive labels. Historical readings and the default version are unchanged ([cmd/orchmeasure/directive_reading.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b36a5ddfe9d70380268d99efa8ad591e13bdb9f8/cmd/orchmeasure/directive_reading.go), [docs/directive-reading-v8.md](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b36a5ddfe9d70380268d99efa8ad591e13bdb9f8/docs/directive-reading-v8.md)).
- **Directive-reading v9 (operator failed-retry attribution).** An explicitly selected `orchmeasure directive-reading --reading-version v9` definition. It requires both `--queue-journal DIR` and `--plans-dir DIR`, and refuses without them. Its emitter uses a failed-retry variant of the evidence collector, so operator retries of failed jobs can be attributed. The blocked-only collector path is kept, so earlier readings stay byte-identical. The report wraps the kernel with the same provenance envelope as v8 (generation time, results and plans directories, and objective, corpus and price-table digests). The partitions array and verification exclusions are carried inside the embedded kernel value. The contract is described in [docs/directive-reading-v9.md](https://github.com/Jeffrey-Keyser/dev-inbox/blob/ccc436c2db6c1b58c60f76ca25b173f5bea2b757/docs/directive-reading-v9.md), with schema [docs/schemas/directive-reading.v9.schema.json](https://github.com/Jeffrey-Keyser/dev-inbox/blob/ccc436c2db6c1b58c60f76ca25b173f5bea2b757/docs/schemas/directive-reading.v9.schema.json) ([cmd/orchmeasure/directive_reading.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/ccc436c2db6c1b58c60f76ca25b173f5bea2b757/cmd/orchmeasure/directive_reading.go), [internal/measurement/directive_reading_v9.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/ccc436c2db6c1b58c60f76ca25b173f5bea2b757/internal/measurement/directive_reading_v9.go)). This implements the design `directive-success-operator-failed-retry-attribution`, now marked `done` ([design/directive-success-operator-failed-retry-attribution/meta.json](https://github.com/Jeffrey-Keyser/dev-inbox/blob/ccc436c2db6c1b58c60f76ca25b173f5bea2b757/design/directive-success-operator-failed-retry-attribution/meta.json)).
- **Directive-reading resume-v1.** An explicitly selected `orchmeasure directive-reading --reading-version resume-v1` definition. It reads operator plan-resume attribution with the same requirement for both `--queue-journal DIR` and `--plans-dir DIR`, and it is the measurement kernel for recorded operator plan resumes ([cmd/orchmeasure/directive_reading.go](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b36a5ddfe9d70380268d99efa8ad591e13bdb9f8/cmd/orchmeasure/directive_reading.go), [docs/directive-reading-resume-v1.md](https://github.com/Jeffrey-Keyser/dev-inbox/blob/b36a5ddfe9d70380268d99efa8ad591e13bdb9f8/docs/directive-reading-resume-v1.md)).
