# Services and Dependencies

## Depends on

### Internal packages (GitHub Packages)

- **`@jeffrey-keyser/pay-auth-integration`**, pinned at `^6.10.1`, used by the server and client. Only public subpaths are allowed ([server/package.json:L30](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/package.json#L30), [client/package.json:L11](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/client/package.json#L11), [AGENTS.md:L8-L12](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/AGENTS.md#L8-L12)).
- **`@jeffrey-keyser/express-server-factory`**, which the app imports for its server setup ([server/app.ts:L2-L3](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/app.ts#L2-L3), [server/package.json:L26](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/package.json#L26)).
- **`@jeffrey-keyser/api-errors`** provides `correlationIdMiddleware` ([server/app.ts:L7](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/app.ts#L7)).
- **`@jeffrey-keyser/message-contracts`** provides event payload types. The inactive `EventPublisher` imports them as types only ([server/services/EventPublisher.ts](https://github.com/Jeffrey-Keyser/ping/blob/03ee2f4b952bdcf9d5397284b5751a50c8d5513c/server/services/EventPublisher.ts)).
- **Other declared server packages:** `database-base-config`, `express-middleware-suite`, `github-error-issues`, and `pay-api-types` ([server/package.json:L24-L29](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/package.json#L24-L29)). - **Client packages:** `feedback-widget`, `personal-ui-kit`, and `redux-app-toolkit` ([client/package.json:L9-L13](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/client/package.json#L9-L13)).

### External services

- **Pay service.** The default URL is `https://pay.jeffreykeyser.net`, overridable by `PAY_SERVICE_URL` ([server/app.ts:L81](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/app.ts#L81), [server/config/env.ts:L145-L146](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/config/env.ts#L145-L146)).
- **Browser push services (Web Push).** Capture-attention alerts are delivered to each subscription's push `endpoint`, which must be an `https://` URL. A 404 or 410 response from the push service removes the stored subscription. The feature is inert unless `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` are set. `VAPID_SUBJECT` falls back to `ORIGIN_BASE_URL` ([server/routes/push-subscriptions.ts](https://github.com/Jeffrey-Keyser/ping/blob/bb7fa57f78b9894f98f4a93fd7b2f50a6974b1c1/server/routes/push-subscriptions.ts), [server/services/CaptureAttentionNotifier.ts](https://github.com/Jeffrey-Keyser/ping/blob/bb7fa57f78b9894f98f4a93fd7b2f50a6974b1c1/server/services/CaptureAttentionNotifier.ts), [server/services/container.ts](https://github.com/Jeffrey-Keyser/ping/blob/bb7fa57f78b9894f98f4a93fd7b2f50a6974b1c1/server/services/container.ts)).
- **Nominatim / OpenStreetMap reverse geocoding (client, explicit opt-in).** The zone creation modal looks up an address only after the user chooses "Send coordinates and look up address". The Map no longer reverse-geocodes on click. The modal's disclosure says the selected coordinates are sent to Nominatim/OpenStreetMap, and that the zone can be created without an address. A failed lookup can be retried by the user ([client/src/containers/Map/Map.tsx](https://github.com/Jeffrey-Keyser/ping/blob/26833b6455f2156606a8b4d25ed51e7c5bf29b55/client/src/containers/Map/Map.tsx), [client/src/containers/Map/components/ZoneCreationModal.tsx](https://github.com/Jeffrey-Keyser/ping/blob/26833b6455f2156606a8b4d25ed51e7c5bf29b55/client/src/containers/Map/components/ZoneCreationModal.tsx), [client/src/containers/Map/Map.placement.test.tsx](https://github.com/Jeffrey-Keyser/ping/blob/26833b6455f2156606a8b4d25ed51e7c5bf29b55/client/src/containers/Map/Map.placement.test.tsx)). The request URL is built in the reverse-geocoding hook, which is not in the excerpts.
- **Analytics Pulse.** `ANALYTICS_PULSE_URL` remains a compatible config value with a default set in config ([server/config/env.ts:L152](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/config/env.ts#L152)). `sendTelemetryEvent` no longer posts to it and has no effect on this sender; telemetry is logged locally ([server/services/telemetry.ts](https://github.com/Jeffrey-Keyser/ping/blob/fa26c56e872f22f1d71dd625498d1404bebcbbef/server/services/telemetry.ts), [docs/designs/local-routine-telemetry.md](https://github.com/Jeffrey-Keyser/ping/blob/fa26c56e872f22f1d71dd625498d1404bebcbbef/docs/designs/local-routine-telemetry.md)). Whether a receiver is live is unknown.
- **Runtime incident transport.** Configured through environment flags; the README points to a coordinated rollout in another repo ([README.md:L142-L144](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/README.md#L142-L144)). Live status is unknown.
- **Cloudflare Tunnel** as public ingress ([README.md:L35](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/README.md#L35)).
- **`beelink-deploy` webhook**, which runs the deploy script ([README.md:L63](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/README.md#L63)). Its configuration is not in the repo.

The collection alerts setting calls `/api/v1/push-subscriptions` directly with `fetch` ([client/src/utils/pushAlerts.ts](https://github.com/Jeffrey-Keyser/ping/blob/bb7fa57f78b9894f98f4a93fd7b2f50a6974b1c1/client/src/utils/pushAlerts.ts)).
- **Shortcut installers** can fetch iCloud links from `/api/v1/shortcuts/links`, which is public ([server/routes/shortcuts.ts:L47-L56](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/routes/shortcuts.ts#L47-L56), [server/app.ts:L108](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/server/app.ts#L108)).

### Routine-event consumers (inactive)

- External consumers of the routine-event feed stop receiving it once the updated process runs. The affected events are location arrivals and departures, Bluetooth connect and disconnect, drive start and end, and workout session completion. No storage transition, package update, or external consumer change is required by the design ([docs/designs/routine-event-channel-inactive.md](https://github.com/Jeffrey-Keyser/ping/blob/03ee2f4b952bdcf9d5397284b5751a50c8d5513c/docs/designs/routine-event-channel-inactive.md), [server/services/EventPublisher.ts](https://github.com/Jeffrey-Keyser/ping/blob/03ee2f4b952bdcf9d5397284b5751a50c8d5513c/server/services/EventPublisher.ts)).
- **Weekly digest delivery is disabled.** Matching `ping-weekly-digest` triggers are acknowledged by `CronSubscriber` without querying personal statistics, formatting a digest, or publishing to `ping.events`. `DigestService.generateAndDeliver` resolves without delivery, so this process does not send a digest toward `openclaw-bridge` or Telegram ([server/services/DigestService.ts](https://github.com/Jeffrey-Keyser/ping/blob/b9a0295b7e1bc91b8abbcf11d527b8fb58aab10a/server/services/DigestService.ts), [server/services/CronSubscriber.ts](https://github.com/Jeffrey-Keyser/ping/blob/b9a0295b7e1bc91b8abbcf11d527b8fb58aab10a/server/services/CronSubscriber.ts)). The routine-event design note still describes digest behavior as unchanged, so that note may be stale ([docs/designs/routine-event-channel-inactive.md](https://github.com/Jeffrey-Keyser/ping/blob/03ee2f4b952bdcf9d5397284b5751a50c8d5513c/docs/designs/routine-event-channel-inactive.md)).

### Documented, not verified

- **Apple Shortcuts on the owner's phone** post to location, mood, health, weight, and expense endpoints ([docs/SHORTCUT_ICLOUD_UPLOAD.md:L77](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/docs/SHORTCUT_ICLOUD_UPLOAD.md#L77), [docs/SHORTCUT_ICLOUD_UPLOAD.md:L94](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/docs/SHORTCUT_ICLOUD_UPLOAD.md#L94)). The repo does not verify installed copies ([docs/MOBILE_INTEGRATION.md:L353](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/docs/MOBILE_INTEGRATION.md#L353)). Shortcuts cannot manage push subscriptions, because that API refuses `X-Ping-Key` with `403` ([server/routes/push-subscriptions.ts](https://github.com/Jeffrey-Keyser/ping/blob/bb7fa57f78b9894f98f4a93fd7b2f50a6974b1c1/server/routes/push-subscriptions.ts)).
- **Expense Shortcut guidance (Wallet automation).** The Expense Logger specification and the in-app expense tutorial now describe a "Ping Expense" Shortcut run by a Wallet automation on each Apple Pay purchase, with Run immediately on and Ask Before Running off, so no per-purchase prompt appears. The body takes `amount` and `merchant` from Shortcut Input, includes `currency` (ISO 4217) only when the input offers it and otherwise omits it, and sends `expenseTimestamp`. `name` and `expenseCategoryId` stay optional and are never prompted. Requests carry `X-Ping-Key` and one `X-Idempotency-Key` per purchase, with the same key, body, and timestamp reused for at most three sends. When there is no Shortcut Input, as in a manual or test run, the Shortcut asks once for the amount only. The specification states it does not update installed Shortcuts ([docs/SHORTCUT_ICLOUD_UPLOAD.md](https://github.com/Jeffrey-Keyser/ping/blob/355db935f9d7c0b42e7a64c098655fd2c397e016/docs/SHORTCUT_ICLOUD_UPLOAD.md), [client/src/containers/Tutorials/data/tutorialData.ts](https://github.com/Jeffrey-Keyser/ping/blob/355db935f9d7c0b42e7a64c098655fd2c397e016/client/src/containers/Tutorials/data/tutorialData.ts), [client/src/containers/Tutorials/__tests__/expenseDelivery.test.ts](https://github.com/Jeffrey-Keyser/ping/blob/355db935f9d7c0b42e7a64c098655fd2c397e016/client/src/containers/Tutorials/__tests__/expenseDelivery.test.ts), [client/src/containers/Tutorials/__tests__/expenseGuide.test.tsx](https://github.com/Jeffrey-Keyser/ping/blob/355db935f9d7c0b42e7a64c098655fd2c397e016/client/src/containers/Tutorials/__tests__/expenseGuide.test.tsx)). This change did not modify server code, so server handling of `merchant` and `currency` is not shown here.
- **`openclaw-bridge`** was previously named in source as the intended RabbitMQ consumer. The inactive publisher no longer carries that comment ([server/services/EventPublisher.ts](https://github.com/Jeffrey-Keyser/ping/blob/03ee2f4b952bdcf9d5397284b5751a50c8d5513c/server/services/EventPublisher.ts)). A drive-related handler is still described in docs ([docs/DRIVE_TRACKING.md:L306-L315](https://github.com/Jeffrey-Keyser/ping/blob/86038591cb036f4b90ee00318760515952cc0ab2/docs/DRIVE_TRACKING.md#L306-L315)). Neither is verified here, so treat it as unconfirmed.
