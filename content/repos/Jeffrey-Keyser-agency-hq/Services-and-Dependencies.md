# Services and Dependencies

Source presence is not proof that an integration is live. Items below separate what the code calls from what documentation expects.

## Depends on

- **PostgreSQL**, `agency` schema in a shared instance ([CLAUDE.md:L49](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/CLAUDE.md#L49)). The `/health` check includes the database ([src/app.ts:L76-L77](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/app.ts#L76-L77)), and startup exits if schema is missing ([src/bin/www.ts:L133-L138](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L133-L138)).
- **RabbitMQ** via `amqplib` ([package.json:L38](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/package.json#L38)). Seven consumers register after connect, including the Logos proposal-card consumer on queue `agency-hq.logos-proposal-cards`; startup continues and reconnects if the broker is down ([src/bin/www.ts:L181-L193](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L181-L193), [src/services/logos-proposal-cards.ts:L130-L139](https://github.com/Jeffrey-Keyser/agency-hq/blob/28c1fbc06d4be757b1d3c3550dfc54a5320e299c/src/services/logos-proposal-cards.ts#L130-L139)). Agency HQ also documents a `daily.summary` topic exchange it declares at startup ([docs/daily-summary-events.md:L7-L18](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/docs/daily-summary-events.md#L7-L18)).
- **Logos API.** Proposal cards read `GET /v1/proposals/{id}` for enrichment, and card taps call `POST /v1/proposals/{id}/approve` or `/reject` with a bearer service token. The base URL comes from `LOGOS_BASE_URL` (default `http://localhost:3070`) and the token from `LOGOS_SERVICE_TOKEN`; the token is read when a call is made, not at startup ([src/services/logos-proposal-cards.ts:L21](https://github.com/Jeffrey-Keyser/agency-hq/blob/28c1fbc06d4be757b1d3c3550dfc54a5320e299c/src/services/logos-proposal-cards.ts#L21), [src/services/logos-proposal-cards.ts:L37-L41](https://github.com/Jeffrey-Keyser/agency-hq/blob/28c1fbc06d4be757b1d3c3550dfc54a5320e299c/src/services/logos-proposal-cards.ts#L37-L41), [src/services/logos-proposal-cards.ts:L160-L184](https://github.com/Jeffrey-Keyser/agency-hq/blob/28c1fbc06d4be757b1d3c3550dfc54a5320e299c/src/services/logos-proposal-cards.ts#L160-L184)). If enrichment fails, the card is still sent with the event fields only ([src/services/logos-proposal-cards.ts:L84-L103](https://github.com/Jeffrey-Keyser/agency-hq/blob/28c1fbc06d4be757b1d3c3550dfc54a5320e299c/src/services/logos-proposal-cards.ts#L84-L103)).
- **dev-inbox.** Dispatch spawns `/home/jkeyser/dev-inbox/scripts/manager-standalone.sh` and reads its results directory (`DEV_INBOX_RESULTS_DIR` override) ([src/execution/dispatcher.ts:L34-L51](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/execution/dispatcher.ts#L34-L51)). The Runs list reads plan manifests next to those results ([src/services/run-list-context.ts:L67-L69](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/services/run-list-context.ts#L67-L69)). Inline Telegram design shipping uses the canonical dev-inbox checkout, chosen from `PROJECT_RECONCILIATION_CANONICAL_DIR`, then `DEV_INBOX_PATH`, then `/home/jkeyser/dev-inbox` ([src/services/project-inline-ship.ts:L15-L16](https://github.com/Jeffrey-Keyser/agency-hq/blob/3e1793848c0fb2d3140f751223e4716c762fa847/src/services/project-inline-ship.ts#L15-L16)). Before reading `design/INDEX.json`, it runs `git fetch` against the design review remote and branch (`DEV_INBOX_DESIGN_REVIEW_REMOTE` and `DEV_INBOX_DESIGN_REVIEW_BRANCH`, default `origin` and `main`), then synchronizes that checkout. The flywheel runner it spawns (`FLYWHEEL_RUNNER`) receives `DEV_INBOX_PATH` pointing at the same checkout ([src/services/project-inline-ship.ts:L31-L70](https://github.com/Jeffrey-Keyser/agency-hq/blob/3e1793848c0fb2d3140f751223e4716c762fa847/src/services/project-inline-ship.ts#L31-L70)). Acceptance readings environments read dev-inbox `results/` and `queue/` read-only ([acceptance/environments/readings-reader.mjs:L1-L11](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/acceptance/environments/readings-reader.mjs#L1-L11), [src/services/project-acceptance.ts:L150-L157](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/services/project-acceptance.ts#L150-L157)).
- **Homelab Stewardship snapshot (read-only).** The snapshot reads without writing: the Logos projection over GET; Dev Inbox `ledger/L-*/requirements.json` and `satisfaction.json`; the Dev Inbox design index `design/INDEX.json` at `origin/main`, with its commit resolved by local `git rev-parse`; the remote default branch of each governed repository through `git ls-remote`; and open GitHub issues through `gh issue list --state open --limit 50`. The issue read is skipped when `HOMELAB_STEWARDSHIP_ISSUES=off`. Acceptance checks, results and reconciliation runs are read from the database ([src/services/homelab-stewardship/collect.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/e1373ec3d1886686eccee7765f302b34c139e23b/src/services/homelab-stewardship/collect.ts), [docs/homelab-stewardship.md](https://github.com/Jeffrey-Keyser/agency-hq/blob/e1373ec3d1886686eccee7765f302b34c139e23b/docs/homelab-stewardship.md)).
- **Credentials.** Startup requires `AGENCY_HQ_API_KEY`, a Feedback Registry token and a JWT signing key, exiting on failure ([src/bin/www.ts:L109-L131](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L109-L131)). The signing key comes from Solo Vault or `AGENCY_HQ_JWT_SIGNING_KEY` ([docs/jwt-authentication.md:L25-L34](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/docs/jwt-authentication.md#L25-L34)); acceptance logins are also fetched from Solo Vault ([src/services/project-acceptance.ts:L194-L215](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/services/project-acceptance.ts#L194-L215)).
- **Model-status sources (documented).** NanoClaw `/model-status` at `127.0.0.1:3101` and the AI Proxy inventory at `127.0.0.1:3005`, both overridable ([docs/model-consumers.md:L36](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/docs/model-consumers.md#L36), [docs/model-consumers.md:L46](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/docs/model-consumers.md#L46)); dev-inbox selector receipts in `results/model-status/` ([docs/model-consumers.md:L34](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/docs/model-consumers.md#L34)).
- **NanoClaw IPC.** `build:deploy` writes a reload request file; whether NanoClaw acts on it is outside this repo ([package.json:L10](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/package.json#L10)).
- **Internal packages:** `database-base-config`, `express-server-factory`, `message-contracts`, `pay-auth-integration`, from GitHub Packages ([package.json:L33-L36](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/package.json#L33-L36), [package.json:L59-L61](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/package.json#L59-L61)). The Logos consumer imports `LogosExchange` and the `logos.proposal.created` routing key from `message-contracts`.

- **Repository-history acceptance checks.** The `repo-history-exec` environment runs owner-declared command argv against a commit and its first parent in disposable worktrees, and caches the outputs and the comparison of the two for reuse across acceptance passes. Output streams are decoded as UTF-8 across chunk boundaries, so multibyte characters do not vary between runs ([acceptance/environments/repo-history-exec.mjs:1-12](https://github.com/Jeffrey-Keyser/agency-hq/blob/ed217bc7bf7ac2343a005868323ef64ac486479f/acceptance/environments/repo-history-exec.mjs#L1-L12)).
