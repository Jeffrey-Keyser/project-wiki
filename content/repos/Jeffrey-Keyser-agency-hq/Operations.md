# Operations

Agency HQ is a deployable service, not a library: `npm start` runs `node dist/bin/www.js` ([package.json:L11](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/package.json#L11)). This page reports what the source and docs say; it did not verify the running host.

## Start

- **Dev:** `npm run dev` runs `ts-node src/bin/www.ts` ([package.json:L7](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/package.json#L7)).
- **Compiled:** `npm run build` then `npm start` ([package.json:L8-L11](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/package.json#L8-L11)).
- **Startup order:** deployment-runtime attestation, API key, Feedback Registry token, JWT signing key, schema validation, a non-fatal `dispatch_config` allowlist scan, then listen and mark ready ([src/bin/www.ts:L101-L177](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L101-L177)). Any fatal step exits with code 1; `EACCES`/`EADDRINUSE` on the port also exit ([src/bin/www.ts:L287-L302](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L287-L302)).

## systemd unit (documented)

- Runs `/usr/bin/node .../releases/agency-hq/current/dist/bin/www.js` from that release directory ([agency-hq.service:L9-L10](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/agency-hq.service#L9-L10)).
- `Restart=always`, `RestartSec=5`, start limit 5 per 60 s, 15 s stop timeout ([agency-hq.service:L5-L14](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/agency-hq.service#L5-L14)).
- `NODE_ENV=production`, `PORT=3040`, optional env files `~/agency-hq/.env` and `~/.config/agency-hq/env` ([agency-hq.service:L17-L20](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/agency-hq.service#L17-L20)).
- The unit has no migration pre-step; run migrations explicitly, or startup fails schema validation ([src/bin/www.ts:L133-L138](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L133-L138)).

## Deploy

Documented: `npm run build` then `systemctl --user restart agency-hq`, with the service file symlinked into `~/.config/systemd/user/` ([CLAUDE.md:L148-L155](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/CLAUDE.md#L148-L155)). Because the unit runs from `releases/.../current`, the step that populates that directory is not shown in these excerpts. Rollout notes describe 'immutable deployment' that drains work and reopens admission ([docs/model-consumers.md:L87](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/docs/model-consumers.md#L87)). `npm run build:deploy` writes a NanoClaw reload request ([package.json:L10](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/package.json#L10)).

Each release directory carries `dist/deployment-release.json`, which records the exact `revision` the release was built from. The running process reads it once at startup, resolving the path from its own code location rather than the mutable `current` link, and reports it on `/health` ([src/lib/release-revision.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/46c60f23833b813d559b8f2b16624850e9afd3e2/src/lib/release-revision.ts)). The source comments say `deploy.sh` writes that manifest only after asserting the release HEAD matches the requested revision. The environment variable carrying that revision does not reach the systemd service, so the manifest is the source of truth.

## Shutdown

SIGTERM/SIGINT stop listeners, interval services, the projection worker and RabbitMQ, then close the server and stop the deployment runtime; a 10 s timer forces exit ([src/bin/www.ts:L241-L285](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L241-L285)). In-flight meeting and admission records are intentionally left intact for recovery ([src/bin/www.ts:L247-L249](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L247-L249)).

## Health and observability

- `GET /health` reports `database` and `resultWatcher` checks ([src/app.ts:L71-L88](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/app.ts#L71-L88)); `/health` stays open through the external access gate ([CLAUDE.md:L94](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/CLAUDE.md#L94)). The body also carries `revision` immediately after `version`. It is the full commit sha of the running release, or `null` when the release has no readable `dist/deployment-release.json` (for example, a source checkout or a pre-manifest release). The value is read once at startup and a null value never changes the health status ([src/middleware/health-revision.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/46c60f23833b813d559b8f2b16624850e9afd3e2/src/middleware/health-revision.ts), [src/lib/release-revision.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/46c60f23833b813d559b8f2b16624850e9afd3e2/src/lib/release-revision.ts), [src/__tests__/health-revision.test.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/46c60f23833b813d559b8f2b16624850e9afd3e2/src/__tests__/health-revision.test.ts)).
- A separate `/api/v1/health` router is mounted ([src/routes/versions/v1/index.ts:L62](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/routes/versions/v1/index.ts#L62)). Its body includes `service`, `uptime`, `version`, `revision` (the same value as `/health`, or `null`) and a `telemetry` block ([src/routes/versions/v1/health.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/46c60f23833b813d559b8f2b16624850e9afd3e2/src/routes/versions/v1/health.ts), [src/__tests__/health-route.test.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/46c60f23833b813d559b8f2b16624850e9afd3e2/src/__tests__/health-route.test.ts)).
- Logging uses pino ([package.json:L43](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/package.json#L43)); request logs skip `/health` and `/dashboard` ([src/app.ts:L42-L45](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/app.ts#L42-L45)). Errors are logged with the request trace id ([src/app.ts:L96-L106](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/app.ts#L96-L106)). Where logs end up on the host is not documented in these sources.
- Startup logs the attention shadow gate `AHQ_GATE_W2A_NTF_SHADOW` ([src/bin/www.ts:L159-L168](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L159-L168)) and warns about invalid dispatch config rows ([src/bin/www.ts:L143-L156](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/src/bin/www.ts#L143-L156)). The same startup log now includes the release `revision` ([src/app.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/46c60f23833b813d559b8f2b16624850e9afd3e2/src/app.ts)).
- Model status endpoints separate configuration from invocation evidence; process-local evidence becomes unknown after restart ([docs/model-consumers.md:L34](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/docs/model-consumers.md#L34)).
- The Homelab Stewardship snapshot (`GET /api/v1/homelab-stewardship`, and `/export` for the JSON download) reports each source with its status, observation time and commit. Sources that cannot be read are marked unavailable and the snapshot is flagged partial, rather than being omitted. Set `HOMELAB_STEWARDSHIP_ISSUES=off` to skip the GitHub open-issue read ([docs/homelab-stewardship.md](https://github.com/Jeffrey-Keyser/agency-hq/blob/e1373ec3d1886686eccee7765f302b34c139e23b/docs/homelab-stewardship.md), [src/services/homelab-stewardship/collect.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/e1373ec3d1886686eccee7765f302b34c139e23b/src/services/homelab-stewardship/collect.ts)). Snapshot schema v2 keeps the current deployed revision, historical deploy records and live health probes apart, so legacy timestamps are never read as a known current deployment. Missing requirement indexes and classification manifests are reported as coverage gaps, not source failures or test failures ([docs/homelab-stewardship.md](https://github.com/Jeffrey-Keyser/agency-hq/blob/740ab905c5105f7bb658867e907fe0a4a44de0b8/docs/homelab-stewardship.md), [src/services/homelab-stewardship/compose.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/740ab905c5105f7bb658867e907fe0a4a44de0b8/src/services/homelab-stewardship/compose.ts)).
- The Homelab Stewardship page renders each section independently. A section that cannot be drawn, for example because of a malformed field, shows a visible 'could not be shown' message while the other sections still render, and the error is written to the browser console. The status line reports snapshot-level read failures and is also logged to the console. Database timestamps arrive as `Date` objects and are converted to ISO strings when each source is read and again during redaction, so check, result and project times reach the snapshot and its export as strings ([src/services/homelab-stewardship/collect.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/9fa85a7b5c00e2e7c02008c5465509718cf72601/src/services/homelab-stewardship/collect.ts), [src/services/homelab-stewardship/redaction.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/9fa85a7b5c00e2e7c02008c5465509718cf72601/src/services/homelab-stewardship/redaction.ts), [src/routes/dashboard/templates/homelab-stewardship.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/9fa85a7b5c00e2e7c02008c5465509718cf72601/src/routes/dashboard/templates/homelab-stewardship.ts)).

## Backups (documented)

Nightly cron at 02:00 UTC writes gzipped SQL dumps of `agency_hq` to `/home/jkeyser/backups/agency-hq/`, kept 30 days; see BACKUP.md ([README.md:L115-L120](https://github.com/Jeffrey-Keyser/agency-hq/blob/c107e01386cfa76587ccfd868b861936c4eea8b1/README.md#L115-L120)).

Restore safety: `scripts/restore-agency-hq.sh` takes a pre-restore safety dump before it drops `agency_hq`, when that database exists. If the dump fails, or lacks pg_dump's completion trailer, the script aborts before `dropdb`. `AGENCY_HQ_RESTORE_SKIP_SAFETY_DUMP=1` is the explicit override that drops without a dump. When the database does not exist, no safety dump is taken. A failed restore message states whether a safety dump was kept ([scripts/restore-agency-hq.sh](https://github.com/Jeffrey-Keyser/agency-hq/blob/0bebfed651e212d324e75770d23c6f2c583ee70e/scripts/restore-agency-hq.sh), [src/__tests__/restore-agency-hq-script.test.ts](https://github.com/Jeffrey-Keyser/agency-hq/blob/0bebfed651e212d324e75770d23c6f2c583ee70e/src/__tests__/restore-agency-hq-script.test.ts)).
